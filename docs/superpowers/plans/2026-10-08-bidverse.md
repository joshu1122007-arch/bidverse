# BidVerse Implementation Plan

Goal: Build the user's complete hackathon auction marketplace in this empty repository.

Architecture: React/Vite JavaScript SPA, normal CSS, React Router and Supabase. PostgreSQL owns bid validation, concurrency, ownership and winner determination. No separate backend or payment processing.

The user's detailed master prompt is the specification and explicitly authorizes independent implementation directly in this repository.

## Interfaces

- `src/lib/supabase.js`: exports `supabase` (client or null), `isConfigured`.
- `src/lib/format.js`: exports `formatCurrency`, `getMinimumBid`, `categories`, `getAuctionStatus`.
- `src/context/AuthContext.jsx`: exports `AuthProvider`, `useAuth()` returning `{ user, loading, authError }`.
- `src/context/ToastContext.jsx`: exports `ToastProvider`, `useToast()` returning `notify(message, type = 'success')`.
- `src/components/StatePanel.jsx`: default component accepts `title`, `message`, `children`, `loading`.
- `src/components/AuctionCard.jsx`: default accepts `auction`.
- `src/components/CountdownTimer.jsx`: default accepts `endTime`, `onExpire`, `compact`.
- `auction_summaries` view: all auction columns plus `highest_bid`, `bid_count`, `highest_bidder_id`, `winner_id` (only after deadline), `seller_name`, `winner_name`.
- `bid_history` view: all bid columns plus `bidder_name`.
- RPC `place_bid(p_auction_id uuid, p_amount numeric)`.
- Routes `/`, `/explore`, `/auctions/:id`, `/create`, `/dashboard`, `/login`.

## Tasks and ownership

- [x] Root: scaffold dependencies, app/router, shared context, formatting, sample fixtures, navigation, home, cards, styles, deployment config. Test formatting and render all routes on desktop/mobile.
- [x] Database worker: `supabase/schema.sql`, `tests/database.test.js`, README. Test actual SQL in PGlite with auth/storage stubs; document hosted tests still required. Enforce positive finite money, first bid >= starting price, subsequent bids >= highest + 100, row locking and clock after lock, no direct writes to bids, profile privacy, listing lock after bids, owner-only storage.
- [x] Auction worker: Explore, AuctionDetails, BidForm, BidHistory, CountdownTimer. Actual database reads, filters, read-only samples, confirmed RPC success, Realtime plus polling cleanup, countdown and winner refresh.
- [x] Account worker: AuthContext, ProtectedRoute, Login, CreateAuction, Dashboard. Email verification, loading, upload validation/cleanup, own listings/bids/wins, delete only unbid active listings with confirmation.
- [x] Root: integrate, independently review security and UI, execute build and automated checks, fix findings, provide exact SQL/setup/deployment instructions.

## Review focus

1. Missing credentials shows configuration guidance and clearly marked sample listings.
2. Stale bids and two buyers cannot overwrite a higher bid; server computes minimum while locked.
3. Client-clock expiry is display only; PostgreSQL time decides acceptance and winner.
4. Failed image uploads/inserts report errors and never fake success.
5. Deep links and mobile navigation work; busy/empty/error states are accessible.
